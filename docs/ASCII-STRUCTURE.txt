 CURRENT PHASE B IMPLEMENTATION
================================================================================

* Per-folder `apply` / `destroy` blocks with independent `allow` and `grace_seconds`.

* Mutation CodeBuild jobs run `tofu show` on the pinned plan artifact before apply/destroy.
* In-progress and terminal PR comments include Step Functions and CodeBuild console links.

================================================================================
 CURRENT AFTER PR B MILESTONE 2 (feat/isolated-mutation-lanes)
================================================================================

* Three isolated outer Step Functions are deployed:
  `openci-tf` (read), `openci-tf-apply` (apply confirm only), `openci-tf-destroy` (destroy confirm only).
* Three isolated inner Step Functions are deployed:
  `openci-tf-run-folder` (read verbs), `openci-tf-run-folder-apply` (apply/CodeBuild only),
  `openci-tf-run-folder-destroy` (destroy/CodeBuild only).
* Read lane assumes registered readonly `role_name`; mutation lanes assume registered
  `poweruser_role_name` only (missing role fails loudly).
* Intent create stays on the read outer machine; confirmed apply/destroy starts the
  dedicated mutation outer machine selected by resolved safe command.
* Mutation inners submit through the engine CodeBuild state machine only (no init-job
  Lambda invoke permission on mutation lane IAM).
* Account registration stores optional `poweruser_role_name`; DynamoDB `enable_apply`
  remains the intent gate. SSM `enable_apply` is Milestone 1 IAM migration only.

================================================================================
 openci-tf — EXECUTION LANES, STATE MACHINES, AND ROLES  (IMPLEMENTED)
================================================================================

Three isolated lanes. Read work never shares a state machine, an execution
path, or an AWS role with apply/destroy. Each state machine's execution list
is its own audit log.

Registration data lives in DynamoDB:
  * per REPOSITORY : require_approval  (Enterprise repos: PR must be approved
                                        before apply/destroy intents pass)
  * per ACCOUNT    : enable_apply      (whether mutations are allowed there)

--------------------------------------------------------------------------------
HUB ACCOUNT (where openci-tf is installed)
--------------------------------------------------------------------------------

├── Step Function: openci-tf                        ◄── READ LANE
│   │   verbs: plan · validate · drift · report
│   │   audit: execution list = every read-only run
│   │
│   ├── PR comment "In progress" posted immediately
│   │       └── includes ➜ LINK to this Step Function execution
│   │           (user clicks → watches live, can stop it in the console)
│   │
│   ├── ValidateAndResolve ─ folder locks ─ RunFolders (Map)
│   │       └── inner SFN: openci-tf-run-folder
│   │            ├── create temporary credentials by assuming:
│   │            │        ***  OPENCI-TF-EXECUTOR-READONLY  ***
│   │            └── engine executes in: LAMBDA
│   │                 (or CodeBuild if the folder's config says so;
│   │                  if CodeBuild ➜ LINK to the build added to the comment)
│   │
│   └── RenderPR (results) ─ FinalizeRun
│
├── Step Function: openci-tf-apply                  ◄── APPLY LANE
│   │   verb: apply ONLY — started only by the confirm-token flow
│   │   audit: execution list = everything ever applied
│   │
│   ├── PR comment "Apply in progress" posted immediately
│   │       ├── includes ➜ LINK to this Step Function execution
│   │       └── includes ➜ LINK to the CodeBuild job once it starts
│   │           (user clicks → sees the pinned-plan echo and mutation output)
│   │
│   ├── VerifyIntent (token · head SHA · pinned plan)
│   ├── Step Functions Wait (apply grace; stop the outer execution to abort)
│   ├── RunFolders sequential (MaxConcurrency=1, fail-fast)
│   │       └── inner SFN: openci-tf-run-folder-apply
│   │            ├── create temporary credentials by assuming:
│   │            │        ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
│   │            │        └─ role missing? ➜ FAIL LOUDLY, apply impossible
│   │            └── engine executes in: CODEBUILD ONLY (no Lambda path exists)
│   │                 ├── download and verify the pinned plan artifact
│   │                 └── run `tofu show` on the pinned plan, then `tofu apply`
│   │
│   └── RenderPR ("Apply succeeded" + apply output + CodeBuild link)
│       ─ FinalizeRun
│
└── Step Function: openci-tf-destroy                ◄── DESTROY LANE
    │   verb: destroy ONLY — started only by the confirm-token flow
    │   audit: execution list = everything ever destroyed
    │
    ├── PR comment "Destroy in progress" posted immediately
    │       ├── includes ➜ LINK to this Step Function execution
    │       └── includes ➜ LINK to the CodeBuild job once it starts
    │           (user clicks → sees the pinned-plan echo and mutation output)
    │
    ├── VerifyIntent (token · head SHA · pinned destroy plan)
    ├── Step Functions Wait (destroy grace; stop the outer execution to abort)
    ├── RunFolders sequential (MaxConcurrency=1, fail-fast)
    │       └── inner SFN: openci-tf-run-folder-destroy
    │            ├── create temporary credentials by assuming:
    │            │        ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
    │            │        └─ role missing? ➜ FAIL LOUDLY, destroy impossible

    │                 ├── download and verify the pinned destroy plan artifact
    │                 └── run `tofu show` on the pinned plan, then `tofu apply`

--------------------------------------------------------------------------------
TARGET ACCOUNT (each registered account)
--------------------------------------------------------------------------------

├── ***  OPENCI-TF-EXECUTOR-READONLY  ***
│       created by: just target-create-aws-readonly <hub-id>   (every account)
│       permissions: ReadOnlyAccess + state-bucket/lock read-write
│       assumable by: READ lane only
│
└── ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
        created by: just target-create-aws-poweruser <hub-id>  (opt-in accounts)
        removed by: just target-delete-aws-poweruser <hub-id>
        permissions: PowerUserAccess + IAM/CloudFormation escalation Denies
        assumable by: APPLY and DESTROY lanes only
        role absent  ⇒  apply/destroy physically impossible in this account
                        (like a disabled key — the ultimate off switch)

--------------------------------------------------------------------------------
CROSS-LANE ISOLATION GUARANTEES
--------------------------------------------------------------------------------

* The read lane's credential code only knows the READONLY role name; the
  mutation lanes only know the POWERUSER role name. No verb parameter picks
  a role — using the wrong role is structurally impossible, not validated
  away.
* The apply/destroy state machines have no Lambda submit path at all;
  execution_target in .openci_tf/config.yaml applies to read verbs only.
* Apply consumes only tf/plan.tfplan; destroy consumes only
  tf/destroy.plan.tfplan. Cross-application is structurally impossible.
* Two-step confirmation: `tf apply <folders>` creates an intent (gates:
  account enable_apply → folder config allow → repo require_approval →
  fresh pinned plan → head SHA) and posts a single-use token with a 10-minute
  expiry; `tf apply confirm <token>` re-checks the head SHA and starts the
  mutation state machine. Same for destroy.
