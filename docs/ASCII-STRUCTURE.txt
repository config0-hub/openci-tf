================================================================================
 openci-tf — EXECUTION LANES, STATE MACHINES, AND ROLES
================================================================================

openci-tf separates read-only review work from apply/destroy mutation work.
Read work never shares a state machine, execution path, or AWS role with the
mutation lanes. Each state machine has its own execution list for auditability.

Registration data lives in DynamoDB:
  * per REPOSITORY : require_approval  (PR approval required before mutation intent)
  * per ACCOUNT    : enable_apply      (whether mutation intents are allowed)
  * per ACCOUNT    : role_name         (readonly role for plan/drift/report)
  * per ACCOUNT    : poweruser_role_name (mutation role for apply/destroy)

================================================================================
HUB ACCOUNT (where openci-tf is installed)
================================================================================

├── Step Function: openci-tf                        ◄── READ LANE
│   │   verbs: plan · drift · report
│   │   audit: execution list = every read-only run
│   │
│   ├── PR comment "In progress" posted immediately
│   │       └── includes ➜ LINK to this Step Function execution
│   │           (user clicks → watches live, can stop it in the console)
│   │
│   ├── ValidateAndResolve ─ folder locks ─ RunFolders (Map)
│   │       └── inner SFN: openci-tf-run-folder
│   │            ├── create temporary credentials by assuming:
│   │            │        ***  OPENCI-TF-EXECUTOR-READONLY  ***
│   │            └── engine executes in: LAMBDA
│   │                 (or CodeBuild if the folder config requests it;
│   │                  if CodeBuild ➜ LINK to the build added to the comment)
│   │
│   └── RenderPR (results) ─ FinalizeRun
│
├── Step Function: openci-tf-apply                  ◄── APPLY LANE
│   │   verb: apply ONLY — started only by the confirm-token flow
│   │   audit: execution list = everything applied through openci-tf
│   │
│   ├── PR comment "Apply in progress" posted immediately
│   │       ├── includes ➜ LINK to this Step Function execution
│   │       └── includes ➜ LINK to the CodeBuild job once it starts
│   │
│   ├── VerifyIntent (token · head SHA · pinned plan)
│   ├── Step Functions Wait (apply grace; stop the outer execution to abort)
│   ├── RunFolders sequential (MaxConcurrency=1, fail-fast)
│   │       └── inner SFN: openci-tf-run-folder-apply
│   │            ├── create temporary credentials by assuming:
│   │            │        ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
│   │            │        └─ role missing? ➜ FAIL LOUDLY, apply impossible
│   │            └── engine executes in: CODEBUILD ONLY
│   │                 ├── download and verify the pinned plan artifact
│   │                 └── run `tofu show` on the pinned plan, then `tofu apply`
│   │
│   └── RenderPR ("Apply succeeded" + apply output + CodeBuild link)
│       ─ FinalizeRun
│
└── Step Function: openci-tf-destroy                ◄── DESTROY LANE
    │   verb: destroy ONLY — started only by the confirm-token flow
    │   audit: execution list = everything destroyed through openci-tf
    │
    ├── PR comment "Destroy in progress" posted immediately
    │       ├── includes ➜ LINK to this Step Function execution
    │       └── includes ➜ LINK to the CodeBuild job once it starts
    │
    ├── VerifyIntent (token · head SHA · pinned destroy plan)
    ├── Step Functions Wait (destroy grace; stop the outer execution to abort)
    ├── RunFolders sequential (MaxConcurrency=1, fail-fast)
    │       └── inner SFN: openci-tf-run-folder-destroy
    │            ├── create temporary credentials by assuming:
    │            │        ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
    │            │        └─ role missing? ➜ FAIL LOUDLY, destroy impossible
    │            └── engine executes in: CODEBUILD ONLY
    │                 ├── download and verify the pinned destroy plan artifact
    │                 └── run `tofu show` on the pinned plan, then `tofu apply`
    │
    └── RenderPR ("Destroy succeeded" + destroy output + CodeBuild link)
        ─ FinalizeRun

================================================================================
TARGET ACCOUNT (each registered account)
================================================================================

├── ***  OPENCI-TF-EXECUTOR-READONLY  ***
│       created by: just deploy                         (hub account)
│                or just target-create-aws-readonly <hub-id> (remote account)
│       permissions: ReadOnlyAccess + state-bucket/lock read-write
│       assumable by: READ lane only
│
└── ***  OPENCI-TF-EXECUTOR-POWERUSER  ***
        created by: just target-create-aws-poweruser <hub-id>  (opt-in)
        removed by: just target-delete-aws-poweruser <hub-id>
        permissions: PowerUserAccess + IAM/CloudFormation escalation denies
        assumable by: APPLY and DESTROY lanes only
        role absent  ⇒  apply/destroy physically impossible in this account

================================================================================
CROSS-LANE ISOLATION GUARANTEES
================================================================================

* The read lane assumes only the configured READONLY role name; mutation lanes
  assume only the configured POWERUSER role name. No verb parameter chooses a
  role at runtime.
* The apply/destroy state machines have no Lambda submit path; mutation runs
  execute through CodeBuild only.
* Apply consumes only `tf/plan.tfplan`; destroy consumes only
  `tf/destroy.plan.tfplan`.
* Two-step confirmation: `tf apply <folders>` or `tf destroy <folders>` creates
  an intent after account, folder, repository, pinned-plan, and head-SHA checks.
  The matching `tf apply confirm <token>` or `tf destroy confirm <token>` then
  re-checks the head SHA and starts exactly one mutation state machine.

================================================================================
PER-FOLDER CONFIG (.openci_tf/config.yaml)
================================================================================

  account_alias: prod
  execution_target: lambda      # read verbs only

  apply:
    allow: true                 # default false
    grace_seconds: 15           # optional; default 15, max 3600

  destroy:
    allow: true                 # default false
    grace_seconds: 60           # optional; default 60, max 3600
